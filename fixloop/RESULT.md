## Post-mortem (declared gate: photo-tier whole-property stitch)

**Prediction vs outcome.** The declaration (committed in `a81cc55`, before the fix in `184193c`) predicted both
multi-room photo captures would move to PASS. Outcome:

| Run | home photo | holdout photo | Gate |
|---|---|---|---|
| v1 draw (our machine, `fixloop-v1-*` tags, probe output in the commit messages) | +28.2 % -> **+1.2 %**, hall 20.53 -> 7.01 m², adjacency 3 missing -> 1 missing | adjacency wrong -> **correct** (5/5) | FAIL -> FAIL (home still misses living-kitchen) |
| reproducible draw (`make fixloop`, table above) | PASS -> PASS (this draw never triggered defect A) | +13.9 % / overlap 12.4 m² / 5 doorways missing -> **-7.5 % / no overlap / 1 missing** | FAIL -> FAIL |

**Root causes: confirmed.** Both declared mechanisms are confirmed by direct before/after evidence:
* Defect A (gap in header evidence lets a neighbouring room leak in): the hall's spurious 13.7 m² disappeared
  (v1 draw). In the reproducible draw the holdout overlap of 12.4 m² (rooms placed on top of each other) is gone.
* Defect B (doorway between near-identical rooms taken for a mirror): the false "mirror" warning is gone in every
  run and north1's second doorway is detected in both draws.

**Why the gate still fails, with evidence.** In both draws the last failing item is a doorway seen from only one
side: home living-kitchen (the living side measures 1.31 m against 0.86 m, so the loop-closing pair is rejected)
and holdout north1-north2 (north2's side is not detected). The holdout footprint (-7.5 %) is now inside the 8 %
band, but its interval misses the truth because south2 is under-reconstructed (4.96 m² vs 7.86 m²). These are
photo-tier *opening detection* errors from 2-8 views, a different defect from the two that were declared and
fixed, so the fix moved the gate meaningfully (overlap 12.4 m² -> 0; footprint error 13.9 % -> 7.5 %; adjacency
6 errors -> 1; home v1 draw 28.2 % -> 1.2 %) but did not reach it.

**Prediction quality.** Right on mechanism and on the size of the footprint effect; wrong on the gate outcome,
because a third, independent defect (one-sided doorway detection) also fails adjacency. Next fix: when one room
detects a doorway and the room it must lead to has none on the facing wall, place the pair from the one detected
side, with its width interval, rather than rejecting it.

**No other gate regressed** (full benchmark rerun, table above). Opening-width rates moved slightly in both
directions because bridging header gaps also changes which arrangement cells merge in every tier.
